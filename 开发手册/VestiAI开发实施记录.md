### 操作注意

- 创建完整备份和恢复前，先退出 App 或停止源码服务。SQLite 备份接口保证数据库一致性；图片与数据库的整批一致性要求停服操作。
- 自动备份默认位于实际数据目录的同级 `backups/`，不是固定只在源码目录。App 的备份位于其 Application Support 目录下。
- 恢复不包含 API Key，继续使用原有凭证配置。缩略图和日志由程序重新建立。
- 软件回退需要使用匹配版本的代码和已经核验的备份；不要让旧代码直接写入未来版本数据库。
- 备份与恢复完整命令见 [项目 README](../README.md#备份与恢复)。

## 本地启动修复

状态：**已完成源码服务启动修复与验收**。

页面出现连接被拒绝时，本地端口没有服务监听，原进程已退出；日志没有应用崩溃记录，具体退出原因未确定。原启动脚本在终端前台运行，并在服务就绪前提示成功。本次针对这两个已确认的问题修复启动方式。

- `scripts/macos/server.py` 启动独立后台进程，关闭启动终端后仍可访问；等待健康检查通过后才提示就绪。
- 重复启动会复用已核验的服务；端口被其他程序占用时明确报错。
- 新增 `scripts/macos/stop.command`。停止前核验进程命令、进程编号和服务实例，避免误停其他程序。
- 启动日志位于 `data/server-startup.log`；运行状态可用 `.venv/bin/python scripts/macos/server.py status` 查看。
- 新增两个隔离集成测试，验证启动器退出后继续运行、重复启动、停止服务和端口占用处理。共 **40 项测试**、前端语法、Mac 脚本语法和服务配置检查通过。
- 实际服务在启动器退出后保持运行；ego-browser 中重新加载本地首页成功。

这次修复解决源码网页服务的启动与终端生命周期问题；付费任务防重、失败分类和重启恢复由下文第二批交付。

## 第二批：付费与任务可靠

状态：**已完成 P0-03 至 P0-06 的实现与模拟验收，本地源码服务已加载新版本**。

这批让收费操作先确认、重复操作复用同一任务，并在网络异常或应用重启后保留真实进度。自动搭配和聊天 Agent 尚未实现。

### 已交付的变化

| 对应需求 | 实际实现 | 用户可以看到的结果 |
| --- | --- | --- |
| P0-03 | 收费 POST 只发送一次；GET 查询有限重试；收费步骤持久化与原子提交抢占 | 网络断开或提交响应丢失不会自动重新生成；重复确认复用原任务 |
| P0-03 | 授权消费、图片快照、访客次数、任务创建和费用预留同事务 | 并发请求只生成一份本地记录，失败回滚不消耗授权和额度 |
| P0-04 | 有远程 ID 时查询原任务；没有 ID 的提交中任务标为待核实；排队任务恢复与唯一执行 | 页面显示“待核实”或“等待查询”，不会因重启把所有任务改成失败 |
| P0-04 | 成功识别和分割结果缓存，恢复只执行剩余步骤；验证试穿图片可读取才完成 | 下载失败可继续处理，已成功的收费步骤不会重新付费 |
| P0-04 | 按用户保存浏览器任务，服务端提供本人活跃任务；历史显示真实状态 | 刷新页面后继续查看原任务，未知提交不会被当成已完成 |
| P0-05 | 统一模型用量账本与任务、用户、应用累计预算；管理员同样受限 | 页面显示费用估算、剩余金额与待核实费用；预算不足拒绝提交 |
| P0-05 | 识别与分割先一起预留；未配置费用拒绝调用；未知费用保留占用 | 不会把未知价格当免费，也不会先付识别费才发现分割无预算 |
| P0-05 | 记录模型、输入图数、可获得的原始用量；旧试穿与访客费用迁入且避免重复 | 旧收费任务恢复后仍有账本；删除衣物或任务不会删除已记录费用 |
| P0-06 | 报价与确认分开；确认绑定具体衣物、形象照、质量、一次生成、上限与有效期 | 打开弹窗只查看费用，点击确认才取得可消费授权；换照片或质量须重新确认 |
| P0-06 | 确认入口仅用于用户操作，模型业务函数不能自行创建已确认授权 | 仅有报价 ID、未确认、过期、他人授权或扩大参数时都不能生成 |
| 兼容与数据保护 | 数据库版本升级为 `2`，旧状态、远程 ID 和衣物保留，升级前自动备份 | 原有数据继续可用；恢复已入库衣物时保留原图和裁剪图 |

执行入口仍为 `.venv/bin/python -B scripts/check.py`，全程临时数据、模拟模型且禁止真实模型网络调用。

- **86 项 Python 测试通过**，包含原功能回归与预算、授权、并发、未知提交、查询恢复、入库恢复和迁移场景。
- **8 个前端可靠性场景通过**：报价与明确确认、确认／创建响应丢失后原请求恢复、用户隔离、未知状态、缓存下载恢复、未配置价格阻断、Plus 共用授权及服务端活跃任务恢复。
- JavaScript 语法、分页检查、四个 Mac 脚本语法和 Gunicorn 配置检查通过。
- ego-browser 在隔离模拟服务中完成“选择衣物 → 选择形象照 → 查看费用 → 明确确认 → 展示可读取结果”流程，确认只提交一次模拟生成。没有使用真实衣橱或人物照片。
- 已核验真实本地服务没有进行中的任务，再重启加载新版本；健康检查、费用接口和任务接口正常，实际数据库已升为 `2`，自动升级备份校验通过。
- 使用 `code-review` 复核失败与并发边界，并修复旧任务漏账及入库恢复删除已引用原图的问题。

### 使用与核验边界

- 识别与分割的单次费用估算必须在 `.env` 中配置正整数；未配置时页面提示并阻止导入。基础／Plus 暂沿用原有 20／50 分估算，所有配置见 [.env.example](../.env.example) 与 [README](../README.md#模型预算与任务恢复)。
- 预算是本地累计估算的限制，平台真实账单没有接入。已提交失败或结果未知仍保留估算占用，不能声称其实际免费。
- 当前未配置百炼凭证，未调用真实收费模型，未核验真实试穿效果或平台实际账单；本批异常、权限和恢复验证均通过模拟服务完成。
- 本地源码网页已更新。未重建 macOS 安装包，原已安装 App 不会自动包含本批改动。
- 待核实且没有远程 ID 的请求需要先核对平台记录，系统不自动补发收费请求。确认失败的新生成需要用户再次明确确认。
